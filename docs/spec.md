## 1. 概要・コンセプト

### 1.1 プロダクトコンセプト
After Effects（AE）の**高度な表現力・アニメーション制御**と、AviUtl2の**軽快なタイムライン編集（NLE）**を単一環境で融合し、さらに**AIネイティブな操作基盤**をコアに備えた動画編集ソフト。

### 1.2 開発・公開方針・ライセンス
* **フェーズ1（自分専用）:** 自身の動画制作ワークフローに最適化し、毎日実戦投入できるレベルまで操作感と自動化機能を尖らせる。
* **フェーズ2（OSS公開）:** コアエンジン、プロジェクト仕様、プラグイン／シェーダーAPIを疎結合に保ち、オープンソースソフトウェア（OSS）として公開・拡張できる構造を維持する。
* **ライセンス方針:** 本体ソースコードは **MIT / Apache-2.0 デュアルライセンス** で公開する。GPL汚染とWindowsビルド障壁を避けるため、FFmpegは**外部CLI（サイドカー）または動的リンク（LGPL構成）**として本体から分離する。

### 1.3 コアUX原則
1. **理解しやすい2空間分離（Dual-Workspace UX）**
   * 軽快にカット・配置を行う「メイン編集空間（AviUtl2ライク）」と、精密な演出を作る「モーション合成空間（AEライク）」を分離し、画面の情報過多と操作の複雑化を防ぐ。
2. **ワンクリック結合＆自動キャッシュ（Smart Precompose）**
   * AE空間で作成した複数レイヤーの複雑な演出を、ワンクリックで1つのクリップ（コンポジション・オブジェクト）に結合し、メイン編集空間へ移送できる。裏側で自動GPUキャッシュを行うことで、メイン空間では通常の動画クリップと同じ60fpsの軽快さを維持しつつ、ダブルクリックでいつでも非破壊の再編集が可能。
3. **人間とAIの完全対等な操作系**
   * GUI操作とAI（内蔵MCP）からの操作がすべて同一の `Command Bus` を経由する。AIが行った編集もすべて `Ctrl+Z` で安全にUndo/Redoでき、操作ログとして永続化される。

## 2. 機能仕様（Functional Specifications）

### 2.1 メイン編集空間（AviUtl2準拠領域）
* **自由レイヤー型タイムライン**
  * 映像・音声・画像・テキスト・図形・フィルタオブジェクト・結合済みコンポジションを区別なく任意のレイヤーへ配置可能。
  * 分割（カット）、ドラッグによる伸縮、スナップ、複数オブジェクト同時選択・移動、中間点操作に対応。
* **フィルタオブジェクト（AviUtl2忠実再現）**
  * タイムライン上に独立したオブジェクトとして配置し、**直上レイヤーまたは指定レイヤー範囲**に対してエフェクトを一括適用する専用概念として実装する（AEのオブジェクト個別エフェクトチェーンとは別システムとして明確に分離）。
* **音声波形のタイムライン表示**
  * 音声ファイル読み込み時にバックグラウンドで波形ピークデータを生成・キャッシュし、タイムライン上に高精細描画する（無音区間の視認・カット効率の最大化）。
* **グループ制御**
  * 複数レイヤーを束ねて位置・拡大率・回転・不透明度を一括制御できる制御オブジェクトを提供。
* **シーン（プリコンポーズ）**
  * タイムラインの入れ子構造をサポートし、「ワンクリック結合」のデータ基盤として機能する。

### 2.2 モーション・コンポジット空間（AE準拠領域）
* **アニメーション＆グラフエディタ**
  * AviUtl2的な「中間点」とAE的な「キーフレーム」を内部データモデルで統一。
  * **値グラフ／速度グラフ**の両方に対応し、3次ベジェ曲線のハンドル操作による直感的なイージング調整を提供。
* **トラックマット**
  * アルファマット／ルミナンスマット（および各反転）によるレイヤー間の切り抜き・マスク合成。
* **テキストの文字ごとアニメーター**
  * `cosmic-text` + `swash` ベースの動画内テキストレンダラーを用い、1文字単位での位置・スケール・回転・不透明度・出現ディレイ（遅延）アニメーション制御を提供。
* **3Dカメラ制御**
  * レイヤーの3D空間配置（X/Y/Z座標・3軸回転）、カメラの移動・注視点制御・被写界深度（ボケ表現）。
* **エフェクトチェーン（オブジェクト個別）**
  * 各メディア／テキスト／図形オブジェクト自身にスタックされる WGSL シェーダーベースのエフェクトチェーン（ブラー、グロー、色調補正、クリッピング等）、ブレンドモード、エフェクトプリセットの保存・再利用。
  * Render Graph 上では、**① 各オブジェクトの個別エフェクトチェーン適用 → ② レイヤー合成 → ③ タイムライン上のフィルタオブジェクト（指定レイヤー範囲）適用** の順序で明確に評価する。

### 2.3 音声テキスト化・合成音声連携・立ち絵自動化
動画制作における高負荷作業（字幕作成・口パク調整）をネイティブ機能として統合する。

#### A. 自動文字起こし（3モード構成）
1. **ローカル標準モード（無料・オフライン）**
   * `whisper-rs`（`whisper.cpp` バインディング、GPU推論対応）を使用し、タイムライン上の音声からタイムスタンプ付きテキストオブジェクトを自動生成。
2. **高精度AIモード（API連携）**
   * **Gemini API**（音声ファイルのネイティブ解析による高精度な書き起こし・タイムスタンプ抽出）および **Claude API**（文脈補正・誤字修正・読みやすい字幕分割）を呼び出せる連携機能。
   * **セキュリティ・誤送信防止:** APIキーは **OS資格情報ストア（Windows Credential Manager等）** に安全に保管し、`project.json` には一切保存しない。音声データの外部送信前には対象尺・概算コストを表示して明示的な確認を行う。
3. **合成音声（TTS）直接連携モード**
   * 音声認識を介さず、合成音声側からテキストとタイミング情報を直接引き抜く。
   * **ファイルペア自動取込:** `voice.wav` と同名の `.txt` / 音素ラベル（`.lab`）を同時ドロップした際、音声・字幕・音素タイミングを一括配置。
   * **ローカルAPI連携:** VOICEVOX / A.I.VOICE / COEIROINK 等のローカルAPIと接続し、テキスト入力から音声・字幕・母音タイミングを1アクションでタイムラインへ生成。

#### B. 立ち絵の自動口パク（リップシンク）
* **対応素材形式（段階的拡張）**
  * **Phase 3（先行実装）:** PNG差分方式（閉じ口／半開き／開き口、または母音「あ・い・う・え・お」ごとの別PNG画像）。
  * **Phase 4（拡張実装）:** PSDネイティブ対応（PSD内のレイヤー構造を直接読み込み、目パチ・口パク差分を切り替え）。
* **連動方式**
  * **音量連動モード:** 指定した音声レイヤーのRMS音量エンベロープを解析し、閾値に応じて口形状を自動切り替え。
  * **母音連動モード:** 文字起こし結果やTTSの音素情報と連動し、発話母音に応じた口形状を自動選択。
* **UX導線:** 立ち絵オブジェクトのプロパティから「連動する音声レイヤー」を選択するだけで即座に動作する設定レス設計。

### 2.4 AIネイティブ編集基盤（内蔵MCPサーバー）
* **接続方式・セキュリティ**
  * アプリ起動時にローカル専用の **Streamable HTTP（`127.0.0.1`、空きポート自動選択＋設定ファイル/UI表示）** でMCPサーバーを待機させる。
  * 起動時に自動生成する **一時ベアラートークン認証** を必須とし、意図しないローカルプロセスからの不正操作を防ぐ。
* **競合制御・Undo粒度制御**
  * GUIでユーザーがタイムラインやハンドルをドラッグ操作中は排他ロック（またはキュー待機）を行い、AIコマンドとの状態競合を防止する。
  * GUIの連続操作（ドラッグ移動・スライダー調整等）は **Command Coalescing** により1つのUndo単位に集約する。
* **公開ツール群（初期設計）**
  * **状態・読み取り系:**
    * `get_project_summary`（解像度、FPS、尺、シーン一覧）
    * `get_timeline_range(start, end)`（フレーム番号・秒の両指定に対応）
    * `get_object_detail(id)`
    * `get_selection`（現在選択中のオブジェクト・キーフレーム一覧）
    * `get_playhead`（現在の再生ヘッド位置）
    * `render_frame_preview(time, scale?)`（指定時刻のレンダリング結果を画像として返却し、マルチモーダルLLMが視覚的に演出を確認・修正可能にする）
  * **編集系:**
    * `add_object`, `delete_object`, `move_object`, `split_object`, `set_property`, `set_keyframe`, `add_effect`, `update_effect_params`
  * **原子的バッチ実行:**
    * `batch_execute(commands[])` により、AIの複数操作（例：「選択中の字幕すべてに0.1秒ずつズラしてフェードインとイーズアウトを適用」）を1つのUndo単位として実行。

### 2.5 書き出し（Export）仕様
* **基本出力フォーマット:** MP4（映像: H.264 / H.265、音声: AAC）— ハードウェアエンコード（NVENC / QSV / AMF）およびソフトウェアエンコード（CRF / ビットレート指定）対応。
* **透過（アルファ付き）書き出し:** WebM（VP9 + Alpha）および PNG 連番出力に対応（他ソフト連携や素材書き出し用途）。
* **音声書き出し:** プレビューと同一の Audio Graph を通してレンダリングし、プレビューとの音ズレ・音量差をゼロにする（WAV単体書き出しも対応）。
* **UX:** バックグラウンド書き出し、進捗率・残り時間表示、安全なキャンセル機能。

## 4. 技術スタック・システムアーキテクチャ

### 4.1 採用技術スタック（Pure Rust構成）

| レイヤー | 採用技術 | 選定理由・役割 |
| :--- | :--- | :--- |
| **コア言語** | **Rust** | メモリ安全・クラッシュ耐性・`cargo` によるOSS参入障壁の低さ・AI協業開発との親和性 |
| **GPU描画・合成** | **`wgpu` + WGSL** | DX12/Vulkanネイティブ動作。**Linear sRGB（`Rgba16Float`）・Premultiplied Alpha** での高品質合成および将来のカスタムシェーダー実行基盤 |
| **動画内テキスト描画** | **`cosmic-text` + `swash`** | 日本語フォントシェイピング・グリフラスタライズ・GPUテクスチャ化（字幕・文字ごとアニメーター基盤） |
| **UIフレームワーク** | **`egui` + `egui_dock`** | タイムライン・グラフエディタの高速なカスタム描画、`wgpu` とのゼロコピー統合、2空間ドッキング切替 |
| **映像デコード/エンコード** | **FFmpeg（外部CLIサイドカー / LGPL動的リンク）** | MIT/Apache-2.0互換性とビルド容易性を維持しつつ、ハードウェア支援（NVENC / QSV / AMF）および透過出力（WebM / PNG連番）を実現 |
| **音声処理・解析** | **`cpal` + `symphonia` + Audio Graph（自前DSP）** | 低遅延再生、A/V同期マスタークロック、異サンプルレート混在ミキシング、波形ピーク・口パク用RMS解析、書き出し共通ミキサー |
| **文字起こし・外部API** | **`whisper-rs`**, **`reqwest`** | ローカルWhisper GPU推論、Gemini/Claude API呼び出し、TTSローカルAPI連携 |
| **時間表現（コアモデル）** | **有理数タイムベース（Rational Time）** | 内部は `ticks / 60000` 秒等の厳密な有理数表現。29.97/59.94/60/24fps混在やFPS変更・音声サンプル位置との整合性を保証 |
| **AI操作・状態管理** | **Command Bus + 内蔵MCP（Streamable HTTP）** | GUI操作・AI操作・Undo/Redo・Command Coalescing・クラッシュ復旧の一元管理 |

### 4.3 カラーマネジメント基準
* 入力動画の YUV→RGB 変換はメタデータ（BT.709 / BT.601）に従って正確に実施し、合成パイプライン入口で **Linear sRGB（`Rgba16Float`）＋ Premultiplied Alpha** へ変換する。
* ブラー・グロー・不透明度・トラックマット・テキスト縁取りはすべてリニア空間＋Premultiplied Alpha で計算し、エッジの黒ずみ（フリンジ）を防止する。
* プレビュー表示および書き出しの最終段でのみターゲット色空間（sRGB / BT.709）へエンコードする。

## 5. プロジェクト保存仕様（1フォルダ管理方式）

1つのプロジェクトを独立した1つのフォルダで管理する。これにより、AIエージェントからの直接参照、キャッシュの独立管理、Git等での履歴管理を容易にする。

```text
MyVideoProject/
├── project.json          # タイムライン・シーン・キーフレーム・エフェクト定義（人間・AI可読、APIキーは含めない）
├── history.jsonl         # クラッシュ復旧用の追記型コマンドジャーナル
├── assets/               # 「プロジェクト収集」実行時の素材コピー先（任意利用）
├── cache/
│   ├── precomp/          # AE空間からワンクリック結合したクリップの自動GPUキャッシュ（ハッシュ管理）
│   ├── waveforms/        # 音声波形ピーク・口パク用音量エンベロープの事前解析データ
│   └── proxy/            # 高ビットレート動画用の軽量プロキシ
└── exports/              # 動画書き出しのデフォルト出力先
```

### 5.1 アセット参照とキャッシュ運用ルール
* **アセット参照ポリシー:** デフォルトは外部ファイルの**リンク参照（相対パス優先、別ドライブ時は絶対パス）**とし、数GBの動画素材によるディスク圧迫を防ぐ。配布・アーカイブ用に全素材を `assets/` へ集約する**「プロジェクト収集」機能**と、ファイル移動・削除時の**オフラインメディア表示＆再リンクUI**を提供する。
* **キャッシュ無効化と容量管理:** `cache/precomp/` は対象コンポジション・素材・エフェクトパラメータのコンテンツハッシュをキーとし、変更検知時に自動無効化・再生成する。キャッシュ全体にはユーザー設定可能なディスク容量上限を設け、**LRU（最終参照時刻順）**で自動削除する。
